# Web 游戏开发流程

从零到发布的完整流程指南，配合 SDD 工作流使用。

## 全局视角

```
阶段 1：构思 ──► 阶段 2：设计 ──► 阶段 3：原型 ──► 阶段 4：迭代 ──► 阶段 5：打磨 ──► 阶段 6：发布
 （用嘴说）      （写 spec）     （最小可玩）     （玩→改循环）    （美术音效）     （构建部署）
```

## 阶段 1：构思

**目标**：回答三个核心问题

| 问题 | 说明 |
|------|------|
| **这个游戏是什么？** | 用一句话描述核心玩法 |
| **玩家为什么想玩？** | 核心乐趣（成就感？节奏感？策略性？） |
| **范围有多大？** | 多少场景、多少实体、预计多长时间 |

**产出**：一段自然语言描述

**原则**：不写代码，不写文档，只想清楚核心乐趣

---

## 阶段 2：设计

**目标**：将构思变成结构化 spec

**步骤**：

```
1. 创建游戏设计总纲
   @spec-driven-dev init "游戏整体设计" --template game-design

2. 逐个创建模块 spec
   @spec-driven-dev init "核心场景" --template scene
   @spec-driven-dev init "玩家角色" --template entity
   @spec-driven-dev init "计分系统" --template system

3. review 所有 spec
   确保接口能对接、核心交互无遗漏
```

**原则**：
- 只设计核心玩法需要的部分
- 每个 spec 只关注一个模块
- 定义 TypeScript 接口作为代码契约

---

## 阶段 3：原型

**目标**：最快速度让游戏能玩

**步骤**：

```
1. 按依赖顺序生成代码
   核心实体 → 核心场景 → 核心系统
   @spec-driven-dev start src/entities/Player.ts
   @spec-driven-dev start src/scenes/GameScene.ts

2. 用色块代替美术
   矩形 = 玩家，圆形 = 敌人/道具，线条 = 平台/墙壁

3. 跑起来试玩
   npm run dev → 浏览器操作

4. 同步变更到 spec
   @spec-driven-dev sync ...
```

**原则**：
- 丑没关系，能玩就行
- 只实现核心循环：操作 → 反馈 → 结果
- 不做菜单、不做计分、不做特效

---

## 阶段 4：迭代

**目标**：让游戏变得好玩

**循环**：

```
玩一玩 → 记录感受 → 分析问题 → 改代码 → 再玩
```

**每轮问自己**：
1. 操作手感如何？（速度、高度、碰撞范围）
2. 节奏对吗？（太快？太慢？太难？太简单？）
3. 反馈清晰吗？（玩家知道发生了什么吗？）

**SDD 迭代方式**：
- 调数值 → 改 `config/` 下的配置
- 加功能 → `@spec-driven-dev add ... "新功能"` → 写 spec → 生成代码
- 改行为 → 改 spec → `@spec-driven-dev start ...` 重新生成

---

## 阶段 5：打磨

**目标**：让游戏好看、好听、有质感

**按顺序执行**：

| 顺序 | 内容 | 说明 |
|------|------|------|
| 1 | UI/菜单 | 主菜单、暂停、结算界面 |
| 2 | 美术替换 | 色块 → 精灵/动画 |
| 3 | 音效 | 操作反馈音效 |
| 4 | 背景音乐 | 循环 BGM |
| 5 | 粒子特效 | 跳跃烟尘、碰撞火花等 |
| 6 | 屏幕震动/闪烁 | 关键时刻的画面冲击 |
| 7 | 移动端适配 | 虚拟摇杆/按钮 |

---

## 阶段 6：发布

```bash
npm run build
```

上传到静态托管：GitHub Pages / Vercel / Netlify

---

## 人与 AI 的分工

```
人                             AI
──────────────────────────────────────────
1. 说出游戏构思            →   评估可行性
2. 确认方向                →   生成游戏设计 spec
3. review spec，调整       →   生成模块 spec
4. review spec，确认       →   生成代码（原型）
5. 试玩，反馈感受          →   调整参数/逻辑
6. 提出新想法              →   add spec → 实现
7. 确认核心玩法 OK         →   打磨 UI/美术/音效
8. 确认完成                →   构建发布
```

## 核心理念

1. **先玩起来，再好看**：原型验证 > 画面完美
2. **spec 先行，代码跟随**：改 spec 比改代码便宜
3. **小步迭代，频繁试玩**：每次只改一个东西，立刻试玩
4. **配置驱动数值**：数值平衡放在配置文件，不改代码逻辑
